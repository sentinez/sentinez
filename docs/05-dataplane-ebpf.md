# 5. eBPF dataplane (`szdataplane`)

The dataplane attaches an XDP program to a network interface to handle
packets at L3 before they reach the edge.

| Path | Role |
|---|---|
| [bpf/sentinez/senz.c](../staging/src/github.com/sentinez/bpf/sentinez/senz.c) | XDP program `senz_main` |
| [bpf/sentinez/senz_monitor.h](../staging/src/github.com/sentinez/bpf/sentinez/senz_monitor.h) | Counts bytes per source IP |
| [bpf/sentinez/senz_security.h](../staging/src/github.com/sentinez/bpf/sentinez/senz_security.h) | Blocks IPs/CIDRs with an LPM trie |
| `bpf/sentinez/senz_bpfe{l,b}.{go,o}` | Go code + objects generated by `bpf2go` |
| [internal/dmz/dataplane/](../internal/dmz/dataplane/) | `Server` (Start/Stop) and `driver` (loads objects, attaches XDP) |
| [internal/bpf/](../internal/bpf/) | Go API over the maps: `LookupBandwidth`, `BlockCIDR` |
| [hack/net/dev/Makefile](../hack/net/dev/Makefile) | Builds network namespaces for experiments |

## 5.1 XDP program

```c
SEC("xdp") int senz_main(struct xdp_md *ctx) {
    action = bandwidth_handler(ctx);    // always XDP_PASS
    if (action != XDP_PASS) return action;
    return security_rule_handler(ctx);  // XDP_DROP if the IP is in the blocklist
}
```

| Map | Type | Key → Value | Used by |
|---|---|---|---|
| `ip_bandwidth` | `LRU_PERCPU_HASH`, 10240 | `__u32 saddr` → `__u64 bytes` | `bandwidth_handler` adds `data_end - data` |
| `blocklist` | `LPM_TRIE`, 1024, `NO_PREALLOC` | `{prefixlen, ip}` → `__u8` | `security_rule_handler` looks up with prefixlen 32 |

Only IPv4 (`ETH_P_IP`) is handled; other packets get `XDP_PASS`. In
`security_rule_handler`, packets shorter than the Ethernet/IP headers get
`XDP_ABORTED`. The `debug()` macro uses `bpf_printk` (read it with
`cat /sys/kernel/tracing/trace_pipe`; the netns Makefile has a `tracing`
target).

Recompile:

```sh
cd staging/src/github.com/sentinez/bpf/sentinez && go generate .   # bpf2go Senz ./senz.c
```

libbpf/xdp-tools headers come from submodules in `bpf/_submodules`.

## 5.2 Go side

`driver.NewContext()` (singleton): `rlimit.RemoveMemlock()` →
`LoadSenzObjects` → keeps `*SenzObjects`. `AttachXDP(ifIndex)` attaches
`SenzMain` via `link.AttachXDP`. `driver.Exec(fn)` lets callers work with the
maps once the context is initialized.

`dataplane.Server.Start(VETH0)`: looks up interface `veth0`, attaches XDP,
then serves gRPC (`DataPlaneService` only has `Status` in the proto and no
handler is registered yet). `Stop` closes the objects/link and calls
`GracefulStop` on gRPC.

API in `internal/bpf`:

| Function | Description |
|---|---|
| `LookupBandwidth(ip) (uint64, error)` | Sums the per-CPU values of `ip_bandwidth` for an IPv4 address |
| `BlockCIDR(cidr) error` | Adds an LPM key `{prefixlen, ip}` to `blocklist` (IPv4 only) |

Note: `driver` is **in-process** state. The edge calls `LookupBandwidth` in
the `LOG` node, but the edge never loads the eBPF objects (the dataplane is a
different process and the maps are not pinned), so it always returns an
error/0. `BlockCIDR` has no callers yet. See
[12-known-issues.md](12-known-issues.md).

## 5.3 Development netns setup

`hack/net/dev/Makefile` (included from the root Makefile):

```
 netns "client"                 netns "gateway"                    host
 veth-client 203.0.113.2/24 ◄──► veth0 203.0.113.1/24  (XDP)
                                 dmz-uplink 192.168.100.2/24 ◄──► host-uplink 192.168.100.1/24 ──NAT──► Internet
```

| Target | Effect |
|---|---|
| `setup` | `clean` + `create`: netns, veth pairs, IPs, default routes, enables `ip_forward`, MASQUERADE |
| `shell-client` / `shell-gateway` | Opens a shell in the netns |
| `test-public` | From client: `curl http://203.0.113.1:7443` |
| `test-internet` | From gateway: `curl -I https://google.com` |
| `status`, `clean`, `curl`, `tracing`, `tracing.debug` | Show status, clean up, test, read eBPF traces |

Run the dataplane in the gateway netns with `make sz.dataplane.run` (uses
`sudo ip netns exec gateway`).
