# 10. Web console (UI)

[ui/](../ui/) is a **pnpm + turbo** workspace (Node 26, pnpm 12).

```
ui/
├── apps/
│   ├── console/     # sentinez-console — Next.js 16 (App Router), React 19
│   ├── web/         # public website (Next.js)
│   └── template/    # starter app
└── packages/
    ├── ui/          # @sentinez/ui — shared components (shadcn/Tailwind 4)
    ├── proto/       # @sentinez/proto — TypeScript generated from protos (ts-proto)
    ├── eslint-config/
    └── tsconfig/
```

Root commands: `pnpm build | dev | lint | format` (via turbo). In
`apps/console`: `dev` (turbopack), `build`, `start`, `lint`, `typecheck`.

## 10.1 Console

Main dependencies: `axios`, `@simplewebauthn/browser` (passkeys),
`@tanstack/react-table`, `recharts`, `sonner` (toasts), `motion`,
`next-themes`, `lucide-react`.

### Routes

| Route | Contents |
|---|---|
| `/auth`, `/auth/signup` | Password login / sign-up |
| `/auth/passkey/login`, `/auth/passkey/register` | WebAuthn flows |
| `/tenant` | Tenant picker |
| `/console` | Root pages: `domain`, `member` |
| `/console/[domain]/tenant` | Tenant `origin`, `resource` (overview, visitors, upstream latency), `setting` (routing locations, editable server form, raw JSON), `ca-certificates` (list, `new`, `[id]`: upload a PEM bundle with its key, read-only detail with the validity left) |
| `/console/[domain]/security` | `sec-rule` (list, `new`, `[id]`), `rulesets`, `rate-limiter` |
| `/console/[domain]/delivery/cdn` | CDN rules |
| `/console/[domain]/analytic` | `activity`, `logs` (`security/sec-rule`, `security/rulesets`, `egress`) |

### Domain resource context and components

- `app/d/console/[domain]/resource-context.tsx`: `ResourceProvider` wraps the
  domain segment layout, fetching the domain's resource once with
  `getResourceByDomain` and exposing `{ domain, resource, isLoading, error,
  refresh }` via `useResource()`. `isLoading` is true only until the first
  fetch: a `refresh` keeps showing the stored resource. `useResourceId()`
  consumes this context, avoiding redundant network round-trips across tab
  switches; the `ResourceView` / `SettingView` pages take no `domain` prop.
- The Setting tab (`tenant/setting/view.tsx`) is two cards:
  `ResourceOverview` (name, domain, status, ids and timestamps as a 4-column
  grid) and a Routing card listing the locations (`ResourceRouting`, one line
  each: `path → rewrite · upstreams [balancing]`, then their headers) with a
  folded "Show JSON" (`ResourceSettingJson`, serialized only once opened).
  Its Edit button swaps the list for `ServerFields` with Cancel / Save.
- `ResourceLatency` (`resource-latency.tsx`): rendered above the visitor
  chart, queries `getEgressLatency` for the last 24h and shows upstream metrics
  (requests, avg, p50, p95, p99, max in ms).
- `ServerFields` (`server-fields.tsx`): editable form for the edge `Server`
  setting (name, location paths, rewrite rules, balance strategies, origin
  upstreams, and proxy-set request headers), validated and saved with
  `updateResource`. No field is filled in only to restate a default: a blank
  rewrite means "same as the path" (sent as the path, which
  `proxy_rewrite`'s `^/.*$` requires; the edge reads an empty one the same
  way), and the balancing select shows only for several upstreams (one
  upstream sends `BALANCE_STRATEGY_UNSPECIFIED`).
- `lib/type/edge.ts` holds the edge setting helpers: `protocolOf`,
  `schemeOf`, `balanceLabelKey` / `BALANCE_STRATEGIES`, the validation
  patterns, and `headerLinesOf`, the one parser of the "Name: value" header
  lines of a location form and of the events (`headerPairsOf` in the
  explorer).
- `InfoRow` (`components/info-card.tsx`): a label / value line; `compact`
  is the dense, ruled layout of the event detail sheet.
- Egress explorer (`kinds/egress.tsx`): displays the `headers` column (the
  request headers injected or mutated by the edge for the origin) and expands
  them in the event detail sheet.

The logs histogram (`analytic/logs/_explorer/event-histogram.tsx`): a click
on a bar (a drag shorter than 4 px) selects its bucket; a drag zooms the
time range to the time it went over, to the second, however wide the
buckets: the pointer x is mapped over the plot area (the buckets share its
width evenly), the dragged span is shaded and labeled with its times
(`hh:mm:ss – hh:mm:ss`), and the range is at least one second. The shade
and its label are drawn in recharts z-index layers (`ZIndexLayer`) above
the bars, the label above everything, so no bar covers them. The bars
animate (400 ms) with recharts' default `isAnimationActive: 'auto'`, off
for `prefers-reduced-motion`.
`zoomOf` (`time-range.ts`) then picks a resolution at least one shorter
than the current one, shorter still when the range fits one; at the
shortest resolution it is kept, and so are the loaded buckets. The
histogram follows the field filters and the request ids of the search box,
which the API applies; the other words of the box only filter the loaded
page.

Notable components:
`app/console/[domain]/security/components/query-builder.tsx` (the SecRule
expression builder) and `sec-rule-fields.tsx`.

### Calling the API

- `lib/api/{iam,security,tenant}` use axios against `/api`
  (`lib/api/base.ts`). The Next.js route `app/api/[...path]` forwards those
  requests to the server-only `API_BASE_PATH` (default
  `http://sentinez.gateway.apiserver:8080`).
- `lib/api/base.ts` registers an axios request interceptor: every request
  to `/api/...` carries `Authorization: Bearer <token>`, with the token the
  login forms store in `localStorage` (`SENTINEZ_ACCESS_TOKEN_KEY`). No
  header is sent while signed out. An API module gets this by importing
  `API_BASE_PATH` from that file. A rejected or expired token is not handled
  centrally yet (no redirect to the login page).
- `lib/session.ts`: `isSignedIn()` is true while the stored token's `exp`
  is in the future (an expired token is removed); `homePath()` is
  `/console/domain` once a tenant id is stored (`SENTINEZ_TENANT_KEY`),
  otherwise `/tenant`. The login forms go to `homePath()`.
  `redirectFor(pathname)` holds the route rules: a signed-in visitor of
  `/auth/...` goes to `homePath()`; `/tenant` and `/console/...` without a
  valid token go to `/auth`; `/console/domain/...` without a tenant id goes
  to `/tenant`.
- `components/session-redirect.tsx` applies those rules: `SessionRedirect`
  in the root layout starts the navigation while the splash
  (`LoadingEffect`) is still shown, and `RouteGuard` (auth, tenant and console
  layouts) shows a spinner instead of a page the visitor is leaving.
- Every API function is typed with the generated messages of
  `api/proto/sentinez/apps/<domain>/v1`
  (`@sentinez/proto/sentinez/apps/<domain>/v1/...`): it takes an
  `XxxRequest` and returns an `XxxResponse`, e.g.
  `updateSecRule({ id, secRule, updateMask })`. The body is built with
  `XxxRequest.toJSON` and the response parsed with `XxxResponse.fromJSON`, so
  enums, int64, `Timestamp`, `FieldMask` and `bytes` are converted by the
  generated code; there are no hand-written wire interfaces.
- GET query params come from `toQuery(XxxRequest.toJSON(req))` in
  `lib/api/pages.ts` (nested fields become `page.index`, repeated fields are
  sent as `ids=a&ids=b`).
- Pages use the proto models (`SecRule`, `RateLimit`, `Resource`) directly;
  the form <-> model mapping lives in the section's `components/`
  (`secRuleFormOf` / `secRuleOf`, `rateLimitFormOf` / `rateLimitOf`,
  `resourceFormOf` / `resourceOf`).
- `NEXT_PUBLIC_USE_SAMPLE=true` returns sample data when an API call fails
  (useful for UI work without a backend).
- `hooks/use-api.ts`: the `useApi(fn, ...args)` hook manages
  `data/isLoading/error/refresh`, cancels requests with `AbortController`,
  and shows error toasts through `handleStatusError`. Pass `null` as the
  first argument to skip the call.
- The token and user info are stored in localStorage under
  `sentinez.ui.accessToken`, `sentinez.ui.refreshToken`, `sentinez.ui.user`.

## 10.2 Types shared with the backend

`@sentinez/proto` is generated from `api/proto` with `buf generate`
(`useOptionals=messages`, `outputJsonMethods=true`, no services). After
changing a proto, run `cd api && buf generate` and rebuild the proto package
so the UI picks up the new types.
