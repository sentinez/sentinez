# 7. Control plane

The `github.com/sentinez/controlplane` module
([staging/src/github.com/sentinez/controlplane](../staging/src/github.com/sentinez/controlplane/))
holds the domain services. Every domain follows the same layout:

```
<domain>/v1/
├── <domain>.go     # gRPC module: NewService(ctx, conf) + Start() serving over bufconn
├── factory/        # NewDefaultHandler / NewDefaultService: build repo → service → handler
├── handler/        # implements <X>ServiceServer, permission checks, logging
├── service/        # business logic
└── repos/<name>/   # PostgreSQL access (IXxx interface + struct)
```

Scaffolding for each layer lives in `hack/.agent/skills/` (`create-service`,
`create-handler`, `create-repo`, `create-factory`, `create-module`).

## 7.1 Storage layer (`pkg/szstorage/dbx`)

[pkg/szstorage/dbx](../staging/src/github.com/sentinez/pkg/szstorage/dbx/):

- `dbx.Database[T]`: `Insert`, `Select`, `Delete`, `Total`, `Table`,
  `CreatedAt`, `UpdatedAt` (the names of its timestamp columns), plus
  `Exec`, `Query`, `CollectRows`, `CollectOneRow` taking a `query.Query`
  (squirrel's `ToSql()` interface).
- `postgres.New[T](ctx, conf, schema)`, where `schema` is a `dbx.Schema`
  (table, typed columns, indexes, timestamp column names) from
  [controlplane/pkg/schema](../staging/src/github.com/sentinez/controlplane/pkg/schema/)
  (`schema.Tenants()`, ...; `schema.All()` lists them all):
  - The real table name is `<mode>.sentinez.<name>` with `.` replaced by `_`,
    e.g. `dev_sentinez_iam_users`; it must match
    `^(dev|sandbox|prod)_sentinez_[a-z]+(_[a-z]+)*$`.
  - Creates the table (`id TEXT PK`, then the two `TIMESTAMPTZ` columns
    named by `Schema.CreatedAt`/`UpdatedAt`, default `created_at` and
    `updated_at`), adds missing columns in order, then the indexes, in one
    round trip — it **never drops, renames or retypes columns**.
  - A model whose metadata is flattened names its timestamp columns after
    the generated constants: `metadata_created_at` (iam users and accounts,
    tenants, members, resources), `owner_created_at` (secrules, rate
    limits, core rulesets, activities).
  - The same schema builds a go-memdb table (`dbx.MemDBSchema`): centraldata
    keeps every controlplane table in memory this way.
  - Uses one global `pgxpool.Pool` from `SENZ_POSTGRES_URI`.
- Helpers: `SelectBuilder` (+ paging `LIMIT/OFFSET ORDER BY <created at> DESC`
  when `page.index` and `page.size` are > 0), `LimitOffset` (the same
  `LIMIT/OFFSET`, the order left to the caller), `InsertBuilder`
  (`RETURNING id`), `InsertRowsBuilder(db, columns, rows, valuesOf)` (many
  rows in one `INSERT`, e.g. `<Msg>Columns()` with `<Msg>Values`),
  `UpsertBuilder` and `UpdateBuilder` (set the updated-at column
  automatically). The insert builders replace the NUL bytes and invalid
  UTF-8 of string values with U+FFFD, which postgres text cannot hold
  (SQLSTATE 22021). `SelectCoalesce` is gone: a nullable column is declared
  on the proto field (`x_field.nullable`).
- `Schema.ColumnNames()` lists the column names of a schema in order, so a
  repository does not repeat them.
- Transactions: `postgres.NewTX(conf).Begin(ctx)` → `*TxSession`;
  `postgres.WithTx(ss, db)` returns a `Database[T]` bound to the
  transaction; repositories expose `WithTX(ss)`.
- Record IDs: `szrand.NewUUID(szprefix.<Entity>.Key())` =
  `<prefix>_<uuid>` (`user_<uuid>`), one prefix per table from
  [pkg/szprefix](../staging/src/github.com/sentinez/pkg/szprefix/prefix.go)
  (a-z, 2 to 5 chars, never changed once public); proto `id` prefix rules
  must match.

Table names ([pkg/sztable](../staging/src/github.com/sentinez/pkg/sztable/tables.go)):
`iam.users`, `iam.accounts`, `tenant.resources`, `analytic.activities`,
`security.sec_rules`, and the edge event tables `analytic.secrules.events`,
`analytic.ratelimiters.events`, `analytic.corerulesets.events`,
`analytic.httpingress.events`, `analytic.httpegress.events` (see
[Collector](#collector-edge-event-ingest)).

Column-name constants (`User_Email`, `SecRule_Expr`, ...) are generated by
`protoc-gen-go-senz` for messages with the
`x_message.database_model = true` option. Models that also set
`x_message.scanner = true` (every controlplane model and edge event) get
generated row scanners, `<Msg>Columns()`, `<Msg>Values(m)`,
`ScanOne<Msg>(row)` and `Scan<Msg>(rows)` (see
[8.2](08-api-protobuf.md#generated-row-scanners)): a repository selects
`<Msg>Columns()...` and passes `ScanOne<Msg>` to `Select`/`CollectOneRow`
or `Scan<Msg>` to `CollectRows`, with no hand-written `row.Scan`.
`schema_test.go` checks that every column a scanner selects is in its
table schema.

### TimescaleDB: hypertables and continuous aggregates

[pkg/szstorage/dbx/timescale](../staging/src/github.com/sentinez/pkg/szstorage/dbx/timescale/)
is built on `postgres.Open`: it shares the pool and joins the transactions
of `postgres.WithTx`. It needs TimescaleDB (`SENZ_POSTGRES_URI` on the
`sentinez.timescale` container that `hack/timescale-up.sh` starts).

- `timescale.New[T](ctx, conf, timescale.Hypertable{Schema, TimeColumn,
  ChunkInterval, Retention})` creates the `timescaledb` extension, the
  table, its missing columns, the hypertable, its indexes and its
  retention policy, in one round trip. An existing plain table is migrated
  in place (`migrate_data`, its primary key dropped).
  - `TimeColumn` partitions the rows: a `TIMESTAMPTZ` column (default
    the created-at column of the schema) or a `BIGINT` of unix milliseconds, for which the
    `<table>_now()` function the policies need is created.
    `ChunkInterval` defaults to 7 days; a change applies to the new chunks.
  - A unique index of a hypertable must hold its time column, so `id` alone
    is not unique: the key is `(id, <time column>)`, and an insert skips
    its duplicates with `Hypertable.OnConflictDoNothing()`
    (`ON CONFLICT (id, <time column>) DO NOTHING`).
  - `Retention` drops the chunks older than it (none when zero).
- `timescale.NewView[T](ctx, conf, timescale.ViewSchema{...})` creates a
  continuous aggregate (materialized view) over a hypertable, which must
  exist: `time_bucket(Bucket, time)` named `bucket`, the `GroupBy` columns,
  then the `Aggregates` (`Expr`, `As`), refreshed by the `Refresh` policy
  (`StartOffset`, `EndOffset`, `Schedule`) and dropped after `Retention`.
  `RealTime` also aggregates, on query, the buckets not refreshed yet.
  - The view is created `WITH NO DATA`, and backfilled once, up to
    `now - Refresh.EndOffset`, when it did not exist. The real time mode,
    refresh and retention policies apply on every start; a change of the
    definition (source, bucket, `GroupBy`, `Aggregates`) needs a new name.
  - It cannot be created or refreshed inside a transaction. `View.Refresh(ctx,
    from, to)` refreshes a range by hand; `View.CollectRows` queries it.

## 7.2 Authentication & authorization

[controlplane/pkg](../staging/src/github.com/sentinez/controlplane/pkg/):

| Package | Purpose |
|---|---|
| `crypto` | `TokenGenerator(*typepb.Context)` signs an HS256 JWT with secret = base64-decode(`SENZ_SECRET_KEY`); claim `auth` = `Context.String()` (prototext), `exp`, `iat`, `iss` = `sentinez.iam`, `aud` = `sentinez.controlplane`. `BearerTokenVerifier` strips the `Bearer ` prefix and verifies the HMAC (HS256 only), the expiry (required), the issuer and the audience, then parses the `Context` back. `HashPassword`/`CheckPasswordHash` use bcrypt |
| `headers` | `GetAuth(ctx)` returns the caller the `authz` interceptor verified, else reads and verifies the `Authorization` metadata → `Auth{*typepb.Context}`; `Auth.Check(method)` calls `perms.Allow` (fails with `PermissionDenied`); `Auth.IsAdmin()`; `WithAuth(ctx, auth)` |
| `authz` | `Unary()` / `ServerOption()`: the deny-by-default interceptor (see below); `Authorizer`: what a caller may do in the tenants; `Scoped`: limits a list request to the resources of the caller |
| `loginlimit` | `Limiter`: blocks a key after N failed sign-ins in a window; used by IAM |
| `passkey` | `NewWebAuthn(conf)` (RP = `core.Name`, RPID = `SENZ_HOSTNAME`, origins = `ClientOrigins(conf)`, the comma-separated `SENZ_CLIENT_ORIGIN`); in-memory `Store` (WebAuthn sessions + pending `Registration`s, see 7.3) |

`typepb.Context` = `{name, expire_at, user_id, control_plane}`; JWTs expire
after 1 hour.

Authorization has two layers.

**1. Per call: the control plane (`PORTAL` / `ADMIN`).** `authz.Unary()` is
installed on every control-plane gRPC server and on the gateway's local
conns, and denies by default:

- Each RPC may declare `option (sentinez.types.v1.x_method) = {public |
  ignore | control_planes: [...]}`; codegen produces `Get<Service><Method>()`.
- `public` needs no token (a valid one is still read). Any other RPC,
  **including one with no `x_method`**, needs a valid token.
- `perms.Allow(method, cp)` then allows access if the method is nil,
  `public` or `ignore` is set, the list is empty, or `cp` is in the list.
  `ignore` skips only this check, not the token.
- The public RPCs are `Login`, `CreateAccount`, the passkey register/login
  RPCs and the `Status`/`SayHello` ones. `CreateUser` and `DeleteUser` are
  `ADMIN` only.
- `szgrpc.New` and `grpcgateway.NewLocalConn` put `recovery.Unary()` first:
  a panic of a handler fails the call with `Internal` instead of stopping
  the process.

**2. Per tenant: the roles of the caller.** The token holds no tenant and no
role. `authz.Authorizer` reads the memberships (`tenant.members`) of the
caller on every call, so a change of role applies at once.

| Needs | Role (or above) | Calls |
|---|---|---|
| read | `MEMBER` | get a tenant, its members, resources, rules and events |
| write | `LEADER` | create/update/delete a resource, SecRule, RateLimit, CoreRuleset |
| manage | `ADMIN` | update/delete a tenant, create/update/delete a member |
| billing | `SUPER_ADMIN` | change the `plan` of a tenant (what it pays for) |

- Roles rank `SUPER_ADMIN` > `ADMIN` > `LEADER` > `MEMBER`. The `ADMIN`
  control plane does anything.
- A caller outside a tenant gets `NotFound`, so it learns nothing of the
  tenant; one inside it without the role gets `PermissionDenied`.
- A member can only be given a role up to the caller's own, never
  `SUPER_ADMIN` (only the `ADMIN` control plane gives it), and a tenant
  cannot lose its last admin.
- Lists are limited to the tenants/resources of the caller (`TenantIds`,
  `ResourceIds`, `Scoped`). A caller with nothing to see gets an empty list
  without a query: an empty filter would match everything.
- Security rules take the tenant of their resource, not the one of the
  request.

## 7.3 IAM

Protos: [apps/iam/v1](../api/proto/sentinez/apps/iam/v1/). Code:
[apps/iam/v1](../staging/src/github.com/sentinez/controlplane/apps/iam/v1/) — account
and user logic in `service/service.go`, the WebAuthn flows in
`service/passkey.go`.

### Data model: one user, one account per login method

```
User (iam.users)                 Account (iam.accounts)
┌──────────────────────┐         ┌────────────────────────────────────┐
│ id                   │◄────────┤ user_id                            │
│ email  (identity)    │   1 : N │ provider = LOCAL   username,       │
│ full_name            │         │                    password_hash   │
│ control_plane        │         ├────────────────────────────────────┤
└──────────────────────┘         │ provider = PASSKEY credentials[],  │
                                 │                    provider_user_id│
                                 └────────────────────────────────────┘
```

- A **User** is the identity: `iam.users` (`id, email, full_name,
  control_plane`). The email identifies the user — one user per email.
- An **Account** is one way that user signs in: `iam.accounts` (`id,
  user_id, email, username, password_hash, credentials TEXT[], provider
  INTEGER, provider_user_id`).
- `provider` is the enum `iampb.Provider`:

| Provider | Value | Fields it uses |
|---|---|---|
| `PROVIDER_LOCAL` | 1 | `username`, `password_hash` (bcrypt) |
| `PROVIDER_PASSKEY` | 2 | `credentials` (one JSON `webauthn.Credential` per passkey), `provider_user_id` (the WebAuthn user handle) |

Rules the service keeps:

- A user has at most one account per provider. Several passkeys of one user
  are several entries in `credentials` of its single passkey account.
- Every account carries the email of its user.
- Sign-in looks the account up **within one provider**: a password never
  matches a passkey account and the other way round.
- The access token is built from the `User`, whatever account signed in:
  `newAccessToken` takes the control plane from `User.control_plane`
  (`PORTAL` when unspecified). The built-in admin is the only exception: it
  has no row, see `Login`.

### Adding a login method

Emails are not verified, so an account is never attached to a user just
because the email matches:

- **Sign-up** (no token) is only accepted for an email no user owns. It
  creates the `User` and its first `Account` in one transaction
  (`createUserAccount`).
- **An existing user** adds a method only while signed in; the user comes
  from the token, not from the request. Today this exists for passkeys
  (`PasskeyLinkChallenge`).

### RPCs

| RPC | REST | Behavior |
|---|---|---|
| `Login` | `PUT /iam/login` | If username = `SENZ_ADMIN_USERNAME`: compares the password with `SENZ_ADMIN_PASSWORD` in constant time (refused when none is set) and issues an ADMIN token (`user_id = sentinez.admin`). Otherwise: finds the `LOCAL` account by username/email, bcrypt check, loads the user, issues a token. Failed attempts are limited: 10 per account and 50 in all per client in 15 minutes, then `ResourceExhausted` (HTTP 429) until the window ends. The client is the last `X-Forwarded-For` hop |
| `CreateAccount` | `POST /iam/account` | Password sign-up. Rejects (`AlreadyExists`) a username or email used by a `LOCAL` account, the reserved `SENZ_ADMIN_USERNAME`, and an email owned by any user; then creates `User` (PORTAL) + `LOCAL` account |
| `CreateUser` | — (gRPC only) | `ADMIN` control plane only. Creates a `User` without an account if the email is not taken |
| `GetUser` | `GET /iam/user` | By `id` (from `iam.users`); a `PORTAL` caller gets itself or a user of one of its tenants, else `NotFound` |
| `ListUsers` | `GET /iam/users` | Filters `ids`, `emails`, paging. A `PORTAL` caller gets: with `ids`, those that are itself or share a tenant with it; with `emails`, the exact matches (at most 5, to invite them); with neither, itself |
| `UpdateUser` | — | Updates `full_name`, `email` |
| `DeleteUser` | `DELETE /iam/user/{id}` | `ADMIN` control plane only. Deletes the user, its tenant memberships and all its accounts in one transaction |
| `ListAccounts` | `GET /iam/accounts` | Requires a token; filters `ids/emails/user_ids/usernames`; each item carries its `provider`. A `PORTAL` caller gets its own accounts only |
| `Status` | `GET /iam/status` | Requires a token. Calls Greeter.Status over bufconn, returns the `Context` of the token |
| `PasskeyRegisterChallenge` | `GET /iam/passkey/register/challenge` | Passkey sign-up, step 1. Needs an email no user owns |
| `PasskeyLinkChallenge` | `GET /iam/passkey/link/challenge` | Add a passkey to the signed-in user, step 1. Requires a token |
| `PasskeyRegisterVerify` | `POST /iam/passkey/register/verify` | Step 2 of both: verifies the authenticator response, then writes |
| `PasskeyLoginChallenge` | `GET /iam/passkey/login/challenge` | `BeginLogin` for the `PASSKEY` account of the username/email |
| `PasskeyLoginVerify` | `PUT /iam/passkey/login/verify` | `ValidateLogin`, updates the credential (sign count), issues a token |

### Passkey flows

State between the two steps lives in `passkey.Store` (in memory, TTL 1
hour) under the returned `session_id`: the WebAuthn `SessionData` and, for
registrations, a `passkey.Registration{UserId, Email, Handle}`.

**Sign-up** (`PasskeyRegisterChallenge` → `PasskeyRegisterVerify`)

1. Challenge: the input must be an email (`InvalidArgument` otherwise) that
   no user owns (`AlreadyExists`). A random handle is generated; nothing is
   written to the database.
2. Verify: the registration is taken from the store — a session can be
   finished once. `CreateCredential` checks the authenticator response.
   Only then, after re-checking that the email is still free, `User`
   (`full_name` = email) and the `PASSKEY` account are created in one
   transaction. A failed or forged response leaves no rows behind.

**Add a passkey** (`PasskeyLinkChallenge` → `PasskeyRegisterVerify`)

1. Challenge: the user is read from the token. If it already has a passkey
   account, its handle is reused, otherwise a new one is generated.
   `Registration.UserId` is set.
2. Verify: because `UserId` is set, the call must carry the token of that
   same user (`Unauthenticated` / `PermissionDenied` otherwise). The
   credential is appended to the user's passkey account, or the account is
   created if this is the first passkey. If the account's handle differs
   from the one the authenticator was given, the call fails with
   `InvalidArgument` and the client starts again.

**Sign-in** (`PasskeyLoginChallenge` → `PasskeyLoginVerify`)

1. Challenge: finds the `PASSKEY` account by username/email (`NotFound` if
   the user has none) and saves the session.
2. Verify: finds the account by the handle stored in the session
   (`GetByProviderUserId`), validates the assertion, stores the updated
   credential, issues the token for the account's user.

`AccountX` wraps `iampb.Account` to implement `webauthn.User`. The WebAuthn
user handle is `provider_user_id`, an opaque value, so it does not change
when the email does. All passkeys of one user share it.

### Repository lookups

| Method | Use |
|---|---|
| `accounts.GetByProvider(provider, usernameOrEmail)` | Sign-in and uniqueness checks of one login method |
| `accounts.GetByProviderUserId(provider, id)` | Passkey sign-in: account of a WebAuthn handle |
| `accounts.GetByUserId(provider, userId)` | The account of a user for one provider |
| `accounts.GetByUsernameOrEmail(input)` | Any provider — existence checks only, never to authenticate |
| `accounts.DeleteByUserId(userId)` | Used by `DeleteUser` |
| `users.GetByEmail(email)` | Who owns an email |

"Not found" is `szerror.ErrNotFound`; the service helper `found` turns it
into a nil result.

### Upgrading an existing database

`provider` used to be a `TEXT` column that was never filled. The storage
layer adds missing columns but never retypes one (7.1), so a database
created before this model keeps the old column and every lookup by provider
fails. Recreate the accounts table (`<mode>_sentinez_iam_accounts`) or
convert the column by hand. Passkeys registered before the change were
given the email as user handle, so their authenticators only work with
`provider_user_id` = email.

## 7.4 Tenant

Protos: [apps/tenant/v1](../api/proto/sentinez/apps/tenant/v1/). A
`Resource` is `id, tenant_id, server, status`: `server` is the
`edgepb.Server` of the resource, the only place its name
(`server.name`) and domain (`server.resource_domain`) live, and
`server.resource_id` is always the resource `id`. Table
`tenant.resources` (`id, tenant_id, server BYTEA, server_name,
server_resource_domain, status`): `server` is stored as binary protobuf,
`server_name`/`server_resource_domain` are derived from it on every write
(`schema.ResourceServerName`/`ResourceServerDomain`) to filter by. The
service lower-cases the domain as the edge matches it, and refuses a
server without one.

| RPC | REST | Notes |
|---|---|---|
| `ListResource` | `GET /tenant/resources` | Filters `status`, `resource_name` (`server.name`), `resource_domain` (`server.resource_domain`), `tenant_ids` |
| `CreateResource` | `POST /tenant/resource` | `server` with `resource_domain` required |
| `UpdateResource` | `PUT /tenant/resource` | Sets `status`; a `server` replaces the stored one |
| `DeleteResource` | `DELETE /tenant/resource` | |
| `GetResource` | `GET /tenant/resource` | `default=true` → the server without its locations |
| `GetResourceByDomain` | `GET /tenant/resource/{resource_domain}` | Returns the first record matching the domain |
| `Status` | `GET /tenant/status` | |

These RPCs declare `control_planes: [PORTAL, ADMIN]`, and the service checks
the role of the caller in the tenant (see 7.2).

### Collector: edge event ingest

The `szcollector` binary runs two apps: the `CollectorService` gRPC server
and `ingest` ([apps/collector/v1/ingest](../staging/src/github.com/sentinez/controlplane/apps/collector/v1/ingest/)),
which consumes the edge traffic events from Kafka and inserts them, in
batches, in the analytic event tables.

| Topic | Record value | Table | Repository |
|---|---|---|---|
| `sentinez.event.http.secrule` | `secrulepb.SecRuleEvent` | `analytic.secrules.events` | `secruleeventsrepo.NewSecRules` |
| `sentinez.event.http.ratelimit` | `secrulepb.SecRuleEvent` | `analytic.ratelimiters.events` | `secruleeventsrepo.NewRateLimits` |
| `sentinez.event.http.rulesets` | `corerulesetpb.CoreRuleEvent` | `analytic.corerulesets.events` | `coreruleeventsrepo.New` |
| `sentinez.event.http.ingress` | `httppb.IngressEvent` (one per request, from the `logging` handler) | `analytic.httpingress.events` | `httpingresseventrepo.New` |
| `sentinez.event.http.egress` | `httppb.EgressEvent` (one per request proxied to its upstream origin, from the `logging` handler) | `analytic.httpegress.events` | `httpegresseventsrepo.New` |

Flow of a batch:

1. `szkafka.Consumer` polls up to 1000 records. The consumer group is the
   service key (`sentinez.apps.collector.v1`), so the collector replicas
   share the partitions.
2. `Ingest.Handle` groups the records by topic and runs the sink of each
   topic concurrently (one table each).
3. A sink decodes the records (`UnmarshalVT`), drops the undecodable ones
   with a warning, and inserts at most 500 rows per statement. The edge
   gives every event a ULID id; an event without one gets
   `<prefix>_<topic>-<partition>-<offset>`, the same on every replay.
   The events are decoded into messages of their pool (see
   [Event pools](#event-pools)) and go back to it once the batch is
   inserted, so `Create` must not keep them.
4. Once the whole batch is inserted its records are marked; the marked
   offsets are committed periodically, and before partitions move or the
   consumer closes.

Delivery is at least once. An insert error retries the whole batch, with a
backoff from 0.5 s to 30 s, and no other batch is polled meanwhile. The
repositories insert with `ON CONFLICT (id, <time column>) DO NOTHING` (see
[TimescaleDB](#timescaledb-hypertables-and-continuous-aggregates)), so a
replayed batch stores no duplicate.

Tables ([pkg/schema/analytic.go](../staging/src/github.com/sentinez/controlplane/pkg/schema/analytic.go):
`AnalyticSecRulesEvent`, `AnalyticRateLimiterEvent`,
`AnalyticCoreRulesetsEvent`, `AnalyticHttpIngressEvent`,
`AnalyticHttpEgressEvent`) take the fields of
the Kafka messages: arrays as `TEXT[]`/`INTEGER[]`, `action` and `tags` as
`JSONB`, enums as `INTEGER`, `matched_time` (milliseconds) as `BIGINT`,
with `BTREE` indexes on the time column, a composite index on
`(resource_id, <time>)`, and `request_id` on the rule event tables
(`secruleEvents` and `AnalyticCoreRulesetsEvent`; HTTP tables are covered
by their unique `(id, time)` index). The ingress table
has the scalar fields of `httppb.IngressEvent` (`status` `INTEGER`, `asn` and
`timestamp`, in milliseconds, `BIGINT`, the others `TEXT`, headers without
the credential ones); its
`resource_id`/`tenant_id` are set by the edge `DomainBased` stage
(`SetResourceId`/`SetTenantId`). They are not in `schema.All()`: centraldata
does not keep events in memory. The column constants come from
`event_senz.pb.go`, generated by the `generate.sh` of `types/secrule/v1`,
`types/coreruleset/v1` and `types/net/http/v1`.

The egress table has one row per request the edge proxied to its upstream
origin (`httppb.EgressEvent`): `id` is the one of the request's ingress
event, so the two tables join on it; then `upstream` (e.g.
`http://10.0.0.1:8080`), `method`, `scheme` (of the upstream), `path`,
`queries`, `status` (the origin's, 502 when unreachable), `content_type`,
`content_length` (-1 when streamed), `latency_micros`, `timestamp` (when
the request was sent, in milliseconds), `resource_id`, `tenant_id`,
`protocol` (the HTTP version the client used to reach the edge), and
`headers` (the request headers the edge set for the upstream, sorted by
name, credential headers omitted). A request
the edge answered itself (cache, static, blocked) has no egress row.

All the event tables are hypertables
(`schema.EventHypertable(schema, timeColumn)`), partitioned by their time
column (`matched_time`, `timestamp`) in chunks of one day, and kept for
`schema.EventRetention`, 30 days.

Repositories ([apps/collector/v1/repos](../staging/src/github.com/sentinez/controlplane/apps/collector/v1/repos/)) embed `*eventreader.Reader[T]` ([eventreader](../staging/src/github.com/sentinez/controlplane/apps/collector/v1/repos/eventreader/)):

- `Create(ctx, events...)` inserts the events, which must have ids, in one
  statement; `Get`, `Delete`, `WithTx`, `Select()`.
- `Histogram(ctx, *histogram.Filter, *eventfilter.Filter)`: the counts per
  time bucket, see [Histograms](#histograms); the second filter only
  narrows them to some requests and fields, and may be nil.
- `List(ctx, *eventfilter.Filter)`: filters on `ResourceIds`, `RequestIds`,
  and on `matched_time` (`From` inclusive, `To` exclusive; `timestamp` for
  the ingress events), pages with `Page`, and orders by `matched_time DESC`.
- `TopValues(ctx, *eventfilter.Filter, names, limit)`: counts the top
  values of fields over the filtered events.
- `eventfilter` compares fields in their native column types (`INTEGER`,
  `INTEGER[]`, `BOOLEAN`, `TEXT`; `eventfilter.TypedColumn(name, type)`,
  an array type matching any element, `Field.IsArray()`) rather than string
  equality, and
  `Filter.Cond` compiles conditions into an `sq.Sqlizer`. `eventfilter.Selection`
  is an interface satisfied by flat request fields and `EventSelection`.
- The egress repository also provides `LatencyReader` (see
  [LatencyReader](#analytic-event-reads)).
- Their columns and row scans are the generated `<Event>Columns()`,
  `<Event>Values` (for `Create`, through `postgres.InsertRowsBuilder`) and
  `ScanOne<Event>`/`Scan<Event>`.

#### Histograms

[pkg/szstorage/dbx/timescale/histogram](../staging/src/github.com/sentinez/pkg/szstorage/dbx/timescale/histogram/)
keeps, for each event table, one continuous aggregate per
`HistogramInterval`, counting its rows per bucket, resource and key; each
`HistogramResolution` (the range a chart covers) reads the view of its
interval, the resolutions of one interval sharing it:

| Resolution | Interval (view suffix) | Buckets |
|---|---|---|
| 5 minutes | 10 seconds (`_10s`) | 30 |
| 15 minutes | 30 seconds (`_30s`) | 30 |
| 30 minutes | 1 minute (`_1m`) | 30 |
| 1 hour | 1 minute (`_1m`) | 60 |
| 3 hours | 5 minutes (`_5m`) | 36 |
| 6 hours | 10 minutes (`_10m`) | 36 |
| 12 hours | 15 minutes (`_15m`) | 48 |
| 24 hours | 30 minutes (`_30m`) | 48 |
| 2 days | 1 hour (`_1h`) | 48 |
| 7 days | 3 hours (`_3h`) | 56 |
| 30 days | 12 hours (`_12h`) | 60 |

For example `dev_sentinez_analytic_httpingress_events_1m`. A view is
refreshed as often as its buckets fill (10 seconds to 30 minutes), up to a
minute ago (or one bucket, when shorter), over the last 2 hours
(`_lateEvents`; 3 days for the buckets of hours): the events the collector
inserts late, below the watermark (e.g. a Kafka backlog after a restart),
are counted within that window. It is not longer because TimescaleDB
invalidates the whole time range of a transaction: a batch holding one old
event would make every refresh recompute all of it. The views of seconds
keep 7 days (`_secondRetention`), the others `schema.EventRetention`. The
views are real time, so the latest buckets include the rows not refreshed
yet. Their columns are `bucket` (unix milliseconds), `resource_id`,
`tenant_id`, the key and `total`.

The key splits the counts further: the http `status` for the ingress and
egress events, `behavior` for the core ruleset events, none for the secrule
and rate limit events (`Point.Key` is 0).

`Histogram.Points(ctx, *Filter{Resolution, ResourceIds, TenantId, From, To})`
sums the totals over the tenants and returns `[]*Point{Time, ResourceId,
Key, Total}`, oldest first: the buckets of the resolution ending with the
current one, or with the one of `To` (exclusive). `Resolution` is the
proto `typepb.HistogramResolution`; when it is unspecified the range picks
it: the shortest one whose span holds `From`..`To` (`To` defaulting to
now) but one bucket, skipping the views of seconds once `From` is older
than 7 days, else 30 days; 1 hour without `From`. `Filter.Resolve(now)`
honours `From` when set (aligning both ends to bucket boundaries) and caps
the window at `MaxBuckets = 1000`, moving `From` later and setting `Truncated = true`
if exceeded; it returns `Window{Interval, From, To, Truncated}`, which the
analytic histogram and visitor RPCs mirror in their `interval`, `from`, `to`,
and `truncated` response fields. They refuse a `from` or `to`
older than `schema.EventRetention` (`INVALID_ARGUMENT`).

The views cannot be narrowed to a request or a field, so
`Histogram.PointsWhere(ctx, *Filter, sq.Sqlizer)` counts the rows of the source
table instead (`SELECT time_bucket(<interval>, <time>), resource_id, key,
count(*) ... GROUP BY`), the `sq.Sqlizer` adding the conditions. The window,
the resolution and the empty buckets are those of `Points`.
`eventreader.Reader[T].Histogram` picks between the two: the views when
`events` filter is nil or has no conditions, else `PointsWhere` with
`events.Cond(spec.Columns)`.

### Analytic: event reads

The analytic reads the collector tables through
[apps/analytic/v1/repos/events](../staging/src/github.com/sentinez/controlplane/apps/analytic/v1/repos/events/):
`eventsrepo.Events` holds one read-only `Reader[T]` (`List`, `Histogram`,
`TopValues`) per table, built from the collector repos, plus `IngressReader`
(adding `VisitorReader`) and `EgressReader` (adding `LatencyReader`).
Building it syncs the tables and views, as the collector does.

| RPC | REST | Reads |
|---|---|---|
| `ListHttpIngressEvents` | `GET /analytic/events/http-ingress` | `analytic.httpingress.events` |
| `ListHttpEgressEvents` | `GET /analytic/events/http-egress` | `analytic.httpegress.events` |
| `ListSecRuleEvents` | `GET /analytic/events/secrule` | `analytic.secrules.events` |
| `ListRateLimitEvents` | `GET /analytic/events/ratelimit` | `analytic.ratelimiters.events` |
| `ListCoreRuleEvents` | `GET /analytic/events/coreruleset` | `analytic.corerulesets.events` |
| `GetEventHistogram` | `GET /analytic/events/histogram` | the views or table of `kind` |
| `GetEventTopValues` | `GET /analytic/events/top-values` | the table of `kind` |
| `GetEgressLatency` | `GET /analytic/events/http-egress/latency` | `analytic.httpegress.events` |

- A list request has `page`, `resource_ids`, `request_ids`, `filters`, `from` and `to`;
  the latest events come first. A page holds 50 events when unset, at most 500.
- `GetEventHistogram` takes `kind` (`EventKind`), `resolution`
  (`HistogramResolution`), `resource_ids`, `request_ids`, `filters`, `from` and `to`,
  and returns `HistogramPoint{time, resource_id, key, total}`, oldest first,
  plus `from`, `to`, `interval`, and `truncated`.
- `GetEventTopValues` counts field occurrences over `from`..`to`, filtered by
  `resource_ids`, `request_ids`, and `filters`.
- `GetEgressLatency` takes `EventSelection` (defaulting to the last 24h),
  groups by `upstream`, and returns `total`, `avg_micros`, `p50_micros`,
  `p95_micros`, `p99_micros`, and `max_micros` (computed with PostgreSQL
  `percentile_cont`).
- `EventSelection` is the canonical message representing resource, request,
  filter and time range criteria, shared across analytic RPCs.
- Every RPC requires a token. The reads are limited to the resources of the
  tenants the caller is a member of: without `resource_ids` they return
  those only, and a caller with no resource gets an empty answer. The
  `ADMIN` control plane reads all.

#### Event pools

The sinks decode into recycled messages
([controlplane/pkg/pools](../staging/src/github.com/sentinez/controlplane/pkg/pools/)):

| Package | Message | Sinks |
|---|---|---|
| `pools/secrule` | `secrulepb.SecRuleEvent` | secrule, ratelimit |
| `pools/coreruleset` | `corerulesetpb.CoreRuleEvent` | rulesets |
| `pools/httpingress` | `httppb.IngressEvent` | ingress |
| `pools/httpegress` | `httppb.EgressEvent` | egress |

Each package exposes `Pool()`, `Acquire()`, `Release(obj)`, backed by the
pool vtproto generates for the message (`<Msg>FromVTPool`,
`ReturnToVTPool`, see [8.3](08-api-protobuf.md#83-code-generation)).
`ReturnToVTPool` calls `ResetVT`, which keeps the capacity of the repeated
fields for the next `UnmarshalVT`. A sink collects the events of a batch in
a `pools.Batch` and defers its `Close`, which releases them all.

Configuration: `SENZ_KAFKA_BROKERS` (unset: ingest disabled with a warning,
the gRPC server still runs) and the database of `SENZ_POSTGRES_URI`. The
consumer limits that bound its memory are in
[09-core-shared.md](09-core-shared.md#szkafka).

## 7.7 Error codes

[pkg/szerror](../staging/src/github.com/sentinez/pkg/szerror/errors.go)
provides gRPC statuses formatted as `SENZ-<code>: <ERRORS_...>` and
`StatusXxxF(format, ...)` helpers (`NotFound`, `Unauthorized`, `Forbidden`,
`InvalidData`/`InvalidArgument`, `AlreadyExists`, `Internal`,
`Unimplemented`). The sentinels `ErrNotFound`, `ErrInvalidData`,
`ErrUnimplemented` are mapped to HTTP by the gateway. `IsNoRows(err)`
detects `pgx.ErrNoRows`.
