# 10. Web console (UI)

Thư mục [ui/](../../ui/) là workspace **pnpm + turbo** (Node 26, pnpm 12).

```
ui/
├── apps/
│   ├── console/     # sentinez-console — Next.js 16 (App Router), React 19
│   ├── web/         # trang web công khai (Next.js)
│   └── template/    # app mẫu
└── packages/
    ├── ui/          # @sentinez/ui — component dùng chung (shadcn/Tailwind 4)
    ├── proto/       # @sentinez/proto — TypeScript sinh từ proto (ts-proto)
    ├── eslint-config/
    └── tsconfig/
```

Lệnh gốc: `pnpm build | dev | lint | format` (qua turbo). Trong
`apps/console`: `dev` (turbopack), `build`, `start`, `lint`, `typecheck`.

## 10.1 Console

Phụ thuộc chính: `axios`, `@simplewebauthn/browser` (passkey),
`@tanstack/react-table`, `recharts`, `sonner` (toast), `motion`,
`next-themes`, `lucide-react`.

### Route

| Route | Nội dung |
|---|---|
| `/auth`, `/auth/signup` | Đăng nhập / đăng ký bằng mật khẩu |
| `/auth/passkey/login`, `/auth/passkey/register` | Luồng WebAuthn |
| `/tenant` | Chọn tenant |
| `/console` | Trang gốc: `domain`, `member` |
| `/console/[domain]/tenant` | `origin`, `resource` (tổng quan, visitor, bảng latency upstream), `setting` (location định tuyến, form chỉnh sửa server, JSON thô), `ca-certificates` (list, `new`, `[id]`: tải bundle PEM kèm khoá, chi tiết chỉ đọc kèm thời hạn còn lại) của tenant |
| `/console/[domain]/security` | `sec-rule` (list, `new`, `[id]`), `rulesets`, `rate-limiter` |
| `/console/[domain]/delivery/cdn` | CDN rule |
| `/console/[domain]/analytic` | `activity`, `logs` (`security/sec-rule`, `security/rulesets`, `egress`) |

### Context resource theo domain và các component

- `app/d/console/[domain]/resource-context.tsx`: `ResourceProvider` bọc layout
  của segment domain, tải resource của domain một lần duy nhất qua
  `getResourceByDomain` và cung cấp `{ domain, resource, isLoading, error,
  refresh }` thông qua hook `useResource()`. `isLoading` chỉ true cho tới lần
  tải đầu: khi `refresh` thì resource đã lưu vẫn được hiển thị. Hook
  `useResourceId()` sử dụng context này, tránh các lượt gọi mạng trùng lặp khi
  chuyển đổi giữa các tab; các trang `ResourceView` / `SettingView` không cần
  prop `domain`.
- Tab Setting (`tenant/setting/view.tsx`) gồm hai card: `ResourceOverview`
  (tên, domain, status, các id và mốc thời gian dạng lưới 4 cột) và card
  Routing liệt kê các location (`ResourceRouting`, mỗi location một dòng:
  `path → rewrite · upstream [cân bằng tải]`, rồi tới header) kèm mục
  "Show JSON" thu gọn (`ResourceSettingJson`, chỉ serialize khi mở ra). Nút
  Edit thay danh sách bằng `ServerFields` với Cancel / Save.
- `ResourceLatency` (`resource-latency.tsx`): hiển thị bên trên biểu đồ
  visitor, truy vấn `getEgressLatency` trong 24 giờ qua và hiển thị các số liệu
  theo upstream (số request, avg, p50, p95, p99, max theo ms).
- `ServerFields` (`server-fields.tsx`): form chỉnh sửa cấu hình `Server` của edge
  (tên, đường dẫn location, quy tắc rewrite, chiến lược cân bằng tải, upstream
  origin và header gán cho request proxy), được validate và lưu qua `updateResource`.
  Không field nào phải điền chỉ để nhắc lại giá trị mặc định: rewrite để
  trống nghĩa là "giữ nguyên đường dẫn" (gửi đi bằng chính path, vì
  `proxy_rewrite` yêu cầu `^/.*$`; edge cũng hiểu giá trị rỗng như vậy), và
  ô chọn cân bằng tải chỉ hiện khi có nhiều upstream (một upstream thì gửi
  `BALANCE_STRATEGY_UNSPECIFIED`).
- `lib/type/edge.ts` chứa các helper của cấu hình edge: `protocolOf`,
  `schemeOf`, `balanceLabelKey` / `BALANCE_STRATEGIES`, các pattern validate,
  và `headerLinesOf`, bộ parse duy nhất cho các dòng header "Name: value" của
  form location và của event (`headerPairsOf` trong explorer).
- `InfoRow` (`components/info-card.tsx`): một dòng nhãn / giá trị; `compact`
  là layout dày, có kẻ dòng, của sheet chi tiết event.
- Explorer log egress (`kinds/egress.tsx`): hiển thị cột `headers` (các request header
  mà edge đã gán hoặc sửa đổi gửi tới origin) và hiển thị chi tiết trong sheet
  xem event.

Histogram của logs (`analytic/logs/_explorer/event-histogram.tsx`): bấm một
cột (kéo ngắn hơn 4 px) để chọn bucket của nó; kéo chuột để zoom khoảng thời
gian về đúng đoạn đã kéo qua, chính xác tới giây, bất kể bucket rộng bao
nhiêu: toạ độ x của con trỏ được quy đổi trên vùng plot (các bucket chia đều
bề ngang), đoạn kéo được tô màu kèm nhãn thời gian (`hh:mm:ss – hh:mm:ss`),
và khoảng chọn tối thiểu một giây. Vùng tô và nhãn được vẽ trong các lớp
z-index của recharts (`ZIndexLayer`) phía trên các cột, nhãn ở trên cùng,
nên không cột nào che chúng. Các cột có hiệu ứng (400 ms) với mặc định
`isAnimationActive: 'auto'` của recharts, tắt khi `prefers-reduced-motion`. Sau đó `zoomOf` (`time-range.ts`) chọn
resolution ngắn hơn hiện tại ít nhất một bậc, ngắn hơn nữa nếu khoảng vừa;
ở resolution ngắn nhất thì giữ nguyên resolution và các bucket đã tải.
Histogram đi theo các field filter và request id trong ô tìm kiếm,
do API áp dụng; các từ khác trong ô chỉ lọc trang đã tải.

Thành phần đáng chú ý:
`app/console/[domain]/security/components/query-builder.tsx` (trình dựng
expression cho SecRule) và `sec-rule-fields.tsx`.

### Gọi API

- `lib/api/{iam,security,tenant}` dùng axios gọi tới `/api`
  (`lib/api/base.ts`). Route Next.js `app/api/[...path]` chuyển tiếp request
  tới `API_BASE_PATH` chỉ có ở server (mặc định `http://localhost:8080`).
- `lib/api/base.ts` đăng ký một axios request interceptor: mọi request tới
  `/api/...` mang `Authorization: Bearer <token>`, với token mà form đăng
  nhập lưu trong `localStorage` (`SENTINEZ_ACCESS_TOKEN_KEY`). Khi chưa đăng
  nhập thì không gửi header. Module API có được điều này nhờ import
  `API_BASE_PATH` từ file đó. Token bị từ chối hoặc hết hạn chưa được xử lý
  tập trung (chưa chuyển về trang đăng nhập).
- `lib/session.ts`: `isSignedIn()` đúng khi `exp` của token đã lưu còn ở
  tương lai (token hết hạn bị xoá); `homePath()` là `/console/domain` khi đã
  lưu tenant id (`SENTINEZ_TENANT_KEY`), ngược lại là `/tenant`. Form đăng
  nhập chuyển tới `homePath()`. `redirectFor(pathname)` giữ các quy tắc
  route: người đã đăng nhập vào `/auth/...` được đưa tới `homePath()`;
  `/tenant` và `/console/...` khi không có token hợp lệ được đưa về `/auth`;
  `/console/domain/...` khi chưa có tenant id được đưa về `/tenant`.
- `components/session-redirect.tsx` áp dụng các quy tắc đó:
  `SessionRedirect` ở root layout bắt đầu chuyển trang ngay khi splash
  (`LoadingEffect`) còn hiện, và `RouteGuard` (layout auth, tenant và console)
  hiện spinner thay cho trang mà người dùng đang rời đi.
- Mọi hàm API dùng kiểu sinh từ `api/proto/sentinez/apps/<domain>/v1`
  (`@sentinez/proto/sentinez/apps/<domain>/v1/...`): nhận `XxxRequest`, trả
  `XxxResponse`, ví dụ `updateSecRule({ id, secRule, updateMask })`. Body tạo
  bằng `XxxRequest.toJSON`, response parse bằng `XxxResponse.fromJSON`, nên
  enum, int64, `Timestamp`, `FieldMask` và `bytes` do code sinh tự chuyển đổi;
  không có interface wire viết tay.
- Query param của GET lấy từ `toQuery(XxxRequest.toJSON(req))` trong
  `lib/api/pages.ts` (field lồng nhau thành `page.index`, field lặp gửi dạng
  `ids=a&ids=b`).
- Các trang dùng trực tiếp model proto (`SecRule`, `RateLimit`, `Resource`);
  phần map form <-> model nằm trong `components/` của từng mục
  (`secRuleFormOf` / `secRuleOf`, `rateLimitFormOf` / `rateLimitOf`,
  `resourceFormOf` / `resourceOf`).
- `NEXT_PUBLIC_USE_SAMPLE=true` trả dữ liệu mẫu khi API lỗi (tiện phát triển
  UI không cần backend).
- `hooks/use-api.ts`: hook `useApi(fn, ...args)` quản lý `data/isLoading/
  error/refresh`, huỷ request bằng `AbortController`, hiển thị toast lỗi qua
  `handleStatusError`. Truyền `null` làm tham số đầu để tạm không gọi.
- Token và thông tin user lưu ở localStorage với key
  `sentinez.ui.accessToken`, `sentinez.ui.refreshToken`, `sentinez.ui.user`.

## 10.2 Kiểu dữ liệu chung với backend

`@sentinez/proto` được sinh từ `api/proto` bằng `buf generate`
(`useOptionals=messages`, `outputJsonMethods=true`, không sinh service). Khi
đổi proto, chạy lại `cd api && buf generate` rồi build package proto để UI
nhận kiểu mới.
